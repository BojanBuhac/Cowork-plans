Cowork Plans · Power Apps canvas app

Give everyone a clear, self-service way to manage their Copilot Cowork plan.

Cowork Plans puts plan visibility, requests, pauses and approvals in one simple app - so business users choose the plan that fits the way they work, managers approve in a click, and administrators keep everything aligned with organisational policy.

🎁 Free to use and share - worldwide

Why it exists

Plan administration shouldn’t be a ticket queue

Without a front door, people don’t know which plan they’re on, requests arrive over email and chat, approvals get lost, and admins reconcile groups and spending policies by hand. Cowork Plans replaces all of that with one transparent, governed experience.

See your plan

Everyone sees their current assignment, their monthly credit allowance and how the available plans compare - at a glance.

Request an upgrade

Pick the plan that matches the work, add a business justification, choose permanent or temporary, and submit.

Approve in the flow

Requests route to the right manager automatically. The current plan stays active until the request is approved.

Stay in policy

Departments only see the plans they’re entitled to, and every change lands back in the right group and spending policy.

How it works

Four steps, no training required

1

Open the app

The user is recognised automatically - their department, role and current plan are shown on entry.

2

Plan cards show the monthly allowance and what each tier is best for, so the choice is obvious.

3

4

On approval, group membership and the matching spending policy are updated - no manual admin work.

Product tour

Everything the app does, screen by screen

A dashboard people actually understand

Plans are presented as clear cards - allowance, who each tier suits, and what it unlocks. The current plan is badged, and a status panel confirms it’s active.

  • Current plan and status always visible
  • Side-by-side comparison of credit allowances
  • Approval routing shown up front, so there are no surprises

Requesting a plan takes seconds

A confirmation dialog summarises the plan, its user limit and the approving manager, then captures a business justification and whether the change is permanent or temporary - with an end date.

  • Business justification captured with every request
  • Permanent or temporary, with an automatic end date
  • Approver named before the request is submitted

Pause a plan during leave - and protect the budget

Going on holiday or extended leave? Users can pause their subscription to a chosen date instead of consuming credits they won’t use. Pausing can be enabled or disabled centrally.

  • Self-service pause with a return date
  • Avoids spend on unused monthly allowances
  • Optional - administrators decide whether it’s available

Plans tailored to each department

Administrators choose exactly which plans each department can see and request - from the CEO Office to Front Line teams - so entitlements follow organisational policy instead of individual negotiation.

  • Per-department plan entitlements
  • Searchable plan catalogue with descriptions and limits
  • Add new tiers as your programme grows

Configurable in minutes, not sprints

A single settings screen controls the pause group, app administrators, the vacation phrases the app recognises, whether pausing is enabled, and whether manager approval is required.

  • Named app administrators
  • Toggle pause and manager approval on or off
  • Localise the leave keywords the app looks for

Under the hood

Standard Microsoft 365 building blocks

No custom infrastructure to run. The app sits on the platform you already govern - Microsoft Entra groups for membership, SharePoint lists for configuration and request history, and Copilot Cowork spending policies for the limits themselves.

The payoff

What you get on day one

Transparency

People stop asking “which plan am I on?” - and admins get a written record of every request, justification and approval.

Less admin effort

Group membership and spending policy changes follow the approval instead of a manual checklist.

Cost control

Entitlements per department, manager approval for upgrades, and pausing during leave keep consumption intentional.

Deployment guide

Deploy Cowork Plans in your own tenant

Nine steps to stand up the SharePoint data layer, Entra security groups, Cowork spending policies and the Power Platform solution. Allow around 90 minutes end to end.

⬇ Download the solution ⬇ Download the 5 CSV files

Current version: CoworkPlan_1_0_0_9.zip

Before you start - you need

SharePoint Administrator (or site-creation rights), Entra ID Groups Administrator (to create security groups), Copilot/Cowork admin rights (to create spending policies), and System Administrator on the target Power Platform environment. Complete the steps in order - later steps depend on IDs produced by earlier ones.

Download first: the solution package (Step 8) and the five CSV files (Step 2). Both are in the same /solution folder of the repository.

Deployment steps

  1. Create the SharePoint communication site
  2. Download and import the five CSV files as lists
  3. Make Title optional on two lists
  4. Create the five security groups (four plans + Pause)
  5. Copy each security group ID from the URL
  6. Populate Security Group ID on the Cowork Plans list
  7. Create the Cowork spending policies
  8. Import the solution into Power Platform
  9. Post-deployment verification checklist

1 Create the SharePoint communication site

SharePoint Administrator or site-creation permission · ~5 minutes
  1. Go to https://<tenant>.sharepoint.com and select Create site.
  2. Choose Communication site. Do not choose Team site - this site must not be connected to a Microsoft 365 group or Teams; it is used purely as a data repository.
  3. Pick the Standard communication site template (blank is fine).
  4. Complete the fields in the table below.
  5. Select Create site and note the final URL - you will need it in Step 8.

2 Import the five CSV files as lists

Site Owner · ~15 minutes · repeat five times

2.0 Download the five CSV files

They live in the same solution folder as the package you downloaded. Right-click each link and choose Save link as…, keeping the file name exactly as it is:

  • Departments.csv
  • Cowork Plans.csv
  • Department plans.csv
  • Cowork Plan Requests.csv
  • Cowork Plan App Settings.csv

Each CSV was exported from SharePoint and carries its own column schema in the first line, so SharePoint recreates the correct column types automatically. Do not open, re-save or edit the CSV files in Excel - that strips the schema line and every column imports as plain text.

2.1 Import procedure (per file)

  1. On the site home page select + New → List.
  2. Select From CSV.
  3. Select Upload file, choose the CSV, and review the detected column types on the preview screen.
  4. Enter the list name exactly as shown below - the flows and app reference these names literally, including spacing and capitalisation.
  5. Clear the Show in site navigation checkbox (optional; keeps the site tidy).
  6. Select Create and wait for the list to finish provisioning before importing the next one.

2.3 Verify the import

  • Cowork Plans must contain 4 items: Getting Started, Business, Business Plus, Business Catalyst.
  • Cowork Plan App Settings must contain 6 items: Pause Group, Vacation phrases, Pause Enabled, Manager approval, Admins M365 Email, Downgrade approval.
  • Cowork Plan Requests must show all 20 columns (Title, EntraID, Email, Plan, Agents and services, User limit, SecurityGroupID, PreviousSecurityGroupID, Manager Name, Manager Email, Request Status, DepartmentID, Department, Approval needed, Validity, Until, Business justification, Pause, Pause until, ExpiryProcessed).

If a list imported with the wrong columns, delete it (Settings → List settings → Delete this list), then re-import from the original untouched CSV.

3 Make Title optional on the Department plans and Cowork Plan Requests lists

Site Owner · ~4 minutes · repeat on both lists

Neither list uses the built-in Title column - Department plans only stores the DepartmentID/PlanID pair, and Cowork Plan Requests records the requester in its own columns. Title is mandatory by default, which makes the Power Automate “create item” action fail. Turn the requirement off on both lists:

  1. Open the Department plans list.
  2. Select the gear icon → List settings. (If you only see the modern pane, choose List settings → More library settings.)
  3. Under Columns, select Title.
  4. Under Require that this column contains information, select No.
  5. Select OK.
  6. Repeat steps 1–5 on the Cowork Plan Requests list.

Both lists must be changed. If Title is left mandatory on Cowork Plan Requests, every plan request fails at the point the flow writes the row - and the failure surfaces only when a user submits a request, not during deployment.

4 Create the five security groups in Microsoft Entra ID

Groups Administrator or User Administrator · ~10 minutes

One security group is required per plan, plus a fifth group for the pause capability - five groups in total, all of them required. The Power Automate flows add and remove users from these groups, and every Cowork spending policy is targeted at one of them.

The pause group is where users are moved when their consumption is temporarily suspended (for example while they are on vacation or leave). It carries its own spending policy with the minimum credit allowance, so a paused user keeps access but consumes almost nothing until the flow moves them back to their normal plan group.

4.1 Create each group

  1. Go to https://entra.microsoft.com → Groups → All groups → New group.
  2. Complete the form using the values below.
  3. Select Create and repeat for every group in table 4.2.
FieldValue

Group nameSee table 4.2
Membership typeAssigned (must not be dynamic - the flow manages membership)
Entra roles can be assignedNo
OwnersThe account performing this deployment
MembersLeave empty

Why the owner matters: add the deploying account as group Owner on all five groups. A group owner can add and remove members through the Office 365 Groups / Entra connector without any tenant-level admin consent, so the Power Automate flows run under that identity with no extra permissions or application registration.

  3. Copy everything after /groupId/ - that 36-character GUID is the Security Group ID. (The same value appears on the group’s Overview page as Object Id; either source is fine.)

6.2 Fill in Departments and Department plans

  • In Departments, add one item per department: Title = department name exactly as it appears in the users’ Entra Department attribute; Approver = the person who approves requests for that department.
  • In Department plans, add one item per allowed combination: DepartmentID = the ID of the department row, PlanID = the ID of the plan row (1–4). A department only sees the plans listed here.

7 Create the Cowork spending policies

Copilot / Cowork administrator · ~10 minutes

Each plan’s credit allowance is enforced by a spending policy scoped to that plan’s security group. Create one policy per plan, in ascending order of generosity, plus a fifth pause policy for the pause group - five policies in total.

  1. Open the Cowork admin experience and go to Spending policies (or Billing → Spending policies, depending on your admin portal version).
  2. Select New policy (or Create policy).
  3. Policy name - match the plan name so that reporting is readable.
  4. Assigned to - select the security group for that plan (search it by name; confirm the object ID matches the GUID recorded in Step 5).
  5. Limit - the monthly credit cap per user.
  6. Save the policy and repeat for the remaining plans.
Policy nameAssign to security groupMonthly limit per userServices in scope

Cowork – PausedCowork - PausedThe lowest allowance your portal permits - set the smallest selectable credit amount so paused users consume next to nothingCopilot Cowork, Work IQ API

How pausing works: when a user is paused, the flow removes them from their plan group (retaining it in PreviousSecurityGroupID) and adds them to Cowork - Paused, so the minimum-credit pause policy applies. When the pause ends, the flow reverses the move and the original plan policy takes effect again. Pausing is only active when Pause Enabled is true and Pause Group holds a valid group ID.

A user must belong to exactly one plan group at a time. The flow removes the previous group (kept in PreviousSecurityGroupID) before adding the new one - do not add users to these groups manually.

8 Import the solution into the Power Platform environment

System Administrator on the target environment · ~20 minutes

8.1 Prepare the environment

  1. Go to the Power Platform admin centre (https://admin.powerplatform.microsoft.com) → Environments.
  2. Use the dedicated environment for this application (create one with + New if it does not exist: type Production, region matching your tenant, Dataverse enabled).
  3. Confirm the deployment account has the System Administrator security role in that environment.

8.2 Get the solution package

Download the ready-made package - no source environment needed:

⬇ Download the solution

Current version: CoworkPlan_1_0_0_9.zip · view on GitHub

Some browsers flag .zip downloads - choose Keep. Do not unzip the file; Power Platform imports the .zip as-is.

Exporting from your own environment instead? Open make.powerapps.com → Solutions → select the solution → Export solution → Publish all customisations → Next → choose Managed for production (Unmanaged only if you intend to keep customising) → Export.

8.3 Import into the target environment

  1. In make.powerapps.com, switch to the target environment (top-right environment picker).
  2. Go to Solutions → Import solution → Browse, select CoworkPlan_1_0_0_9.zip, then Next.
  3. On the connections page, create or select a connection for each connector used by the solution, signed in as the deployment account:
    • SharePoint - access to the site from Step 1
    • Office 365 Users - reads manager and department attributes
    • Office 365 Outlook - sends approval and notification e-mail
    • Microsoft Entra ID / Office 365 Groups - adds and removes group members (works without extra permissions because the account is a group owner, Step 4)
    • Approvals - manager approval requests
  4. On the environment variables page, enter the tenant-specific values shown below.
  5. Select Import and wait for completion (typically 5–15 minutes).

8.4 Turn on the flows and share the app

  1. Open the imported solution → Cloud flows. Any flow shown as Off must be turned On (open the flow → Turn on).
  2. Open the app → Share → add the user population (for example a broad “All employees” group) with User permission.
  3. Confirm the app’s SharePoint data sources resolve without errors, then Publish the app.

9 Post-deployment verification checklist

~15 minutes · run this end to end before announcing the app
  • Communication site exists and is not group/Teams connected.
  • All five lists exist with the exact names; Cowork Plans has 4 rows and App Settings has 6 rows.
  • Title is no longer mandatory on Department plans - or on Cowork Plan Requests.
  • Five security groups exist, membership type Assigned, deployment account is Owner on each.
  • Every Security Group ID in Cowork Plans matches a group in this tenant (no leftover source-tenant GUIDs).
  • Pause Group in App Settings holds the object ID of the Cowork - Paused group.
  • Admins M365 Email in App Settings holds the primary administrators’ addresses (sample addresses removed).
  • Departments and Department plans populated for at least one pilot department.
  • Five spending policies created (four plans + pause), each targeting the correct security group; the pause policy uses the minimum credit allowance.
  • Solution imported, all connections green, all flows On, app published and shared.

Smoke test: submit a plan request as a pilot user → the approval reaches the manager → approve → a new row lands in Cowork Plan Requests with the correct SecurityGroupID → the user appears in the matching Entra group within a few minutes → the spending policy applies to that user.

Rollback: if the smoke test fails, turn the flows Off, correct the configuration (usually a list name, an environment variable, or a mismatched group ID), turn the flows back On and re-run the test. No data is lost - all state lives in the SharePoint lists.
